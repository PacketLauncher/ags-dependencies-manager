In order to compile the AGS Engine and Editor from its source code in Visual Studio, you must point it to some dependencies.

The dependencies archive is called 'WinDevDependenciesVS.zip' and it's available for download under the 'Assets' section of the release you're willing to compile. This repository includes a copy of them from 'AGS v3.6.2 - P12 (3.6.2.22)', but you can refer to https://github.com/adventuregamestudio/ags/releases to download it from there (new released may include more dependencies in this package and may require editing this dependencies manager script).

Generally, you would need to copy the dependencies to their corresponding folders when you download the AGS source before you could compile the Engine and Editor, or else you'd get errors that they're missing. However, if you're working on multiple ags source copies on your system for different development aspects, that means that each of them must have a separated copy of the same dependencies, which is not easy to manage and waste of disk space. This dependencies manager script comes to solve this problem; note that some dependencies still required to be present in the '\Editor\References' folder for the AGS Editor to compile - more on this below.


How to use:
-----------
1. Download a specific ags release source code or use the 'ags-master' from https://github.com/adventuregamestudio/ags. Then extract it to a folder of your choice.

2. Download and extract the 'WinDevDependenciesVS.zip' to a shared location on your system for all ags source projects to access, such as 'C:\WinDevDependenciesVS'.

3. Copy the 'AGS_Dependencies_Manager.bat' script to the extracted folder.

4. Access the folder and launch the 'AGS_Dependencies_Manager.bat' script.

5. From the CLI menu, choose the 1st option to install* the dependencies path on your system.

* If you ever wish to remove the dependencies paths entires from your system, re-launch the 'AGS_Dependencies_Manager.bat' script and select the 2nd option. It will then remove any path entry it added for this folder.

6. Still in the CLI, choose the 3rd option. It will ask you to provide the path to the AGS source directory. Drag and drop the extracted AGS source folder that you extracted in the previous step on-top of the CLI window, or copy and paste its full path. Then hit Enter. It will copy* all necessary dependencies to the '\Editor\References' folder.

* If you ever wish to remove dependencies that were copied to the '\Editor\References' folder of one of your ags source directories, re-launch the 'AGS_Dependencies_Manager.bat' script and select the 4th option. It will ask you to provide the path to the AGS source directory the same as when installing them. Drag and drop the extracted AGS source folder on-top of the CLI window, or copy and paste its full path. Then hit Enter. The dependencies will be removed from the '\Editor\References' folder.

~ The following steps require Visual Studio to be present on your system; you can download Visual Studio Community edition for free directly from Microsoft ~

7. From the AGS source 'Solutions' folder, double-click on both "Engine.sln" and "AGS.Editor.Full.sln" to open the projects in Visual Studio. When each of them opens, make sure that the top bar is set to "Debug" and "Win32/x86".

8. In the 'Engine' project, right-click on the "Engine.App" entry under the solutions panel and select "Set as Startup Project" so it will be in bold.

9. In the 'AGS.Editor.Full' project, right-click on the "AGSEditor" entry under the solutions panel and select "Set as Startup Project" so it will be in bold.

10. Building each project can be done by selecting 'Build -> Build Solution' from the top menu, or by hitting CTRL+B. For testing the Editor, make sure that you're on the 'AGS.Editor.Full' project and hit F5 to launch it (the project will be compiled to "Solutions\.build\x86\Debug").

11. When you're ready to release, change at the top bar in both projects from "Debug" to "Release". Then in both of them, select 'Build -> Build Solution' from the top menu, or hit CTRL+B (the project will be compiled to "Solutions\.build\x86\Release").


I've made 2 standalone programs for cleaning up folders of Visual Studio projects for making clean backups of them for your convenience:
 - Project-Difference-Backup (https://github.com/PacketLauncher/Project-Difference-Backup): this program makes a backup of ONLY the files you modified by comparing them with their original source. It also saves the originals for reference, and preserves folders hierarchy and timestamps.
	
- Modified-Project-Folder-Cleaner (https://github.com/PacketLauncher/Modified-Project-Folder-Cleaner): this program makes a clean backup of the ENTIRE modified project folder by comparing it with its original source, excluding any dependencies and leftovers that were generated by Visual Studio when compiling it.
